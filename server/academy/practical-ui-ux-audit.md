# Practical UI/UX Audit
RizQara Tech Academy · Beginner · 3 lessons, templates, and a design exercise

## Project brief
Design a clearer booking flow for a fictional small clinic. Use sample data and avoid collecting health or identity information. The goal is to request a consultation by choosing a date and time and reviewing the request.

## Lesson 1 — Define the task
Write a task without naming the controls: “Find a time next Tuesday afternoon and check what happens after you submit.” Identify the starting page and the expected end state. Separate issues in navigation, selecting a time, and understanding confirmation.

Exercise: list the minimum information a person needs at each step. Keep time zone, availability, and how changes are handled visible at the point where they matter.

Classify issues as blocks task, adds friction, or cosmetic. One reproducible observation is enough to record a finding, with the sample size stated where relevant. Avoid generalizing from a single person.

Exercise: record one keyboard issue, one copy issue, and one mobile layout issue. If you use a mock interface, clarify that the findings come from a practice audit.

## Lesson 3 — Redesign and retest
Create two versions of the date picker and confirmation screen. In the revised version, keep the selected time visible and explain whether the appointment is confirmed or awaiting approval. Try the same task with a small number of people who have not seen your design. Ask them to talk through the decision, without telling them what to click.

## Usability test script
- “Please find an appointment next Tuesday afternoon.”
- “Before you submit, tell me what you think will happen.”
- “Now try changing the time.”
- “What information, if any, was missing?”

Log task completion, errors, and questions. Show the original and revised flow with the specific findings you addressed.

## Check your understanding
A user selects a time but misses an “awaiting approval” label. What should change?
Suggested answer: place the status beside the selected time and repeat it on the confirmation screen. Retest whether users can explain the status in their own words.
